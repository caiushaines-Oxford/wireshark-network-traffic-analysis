**Investigation Date:** 16 November 2026  
**Analyst:** Caius Haines  
**Tools Used:** Wireshark  
**Investigation Type:** Network Traffic Analysis  
**Classification:** Training Exercise / Baseline Traffic Investigation

## 1. Executive Summary

A practical network traffic investigation was conducted using Wireshark to examine DNS queries, TCP connections and HTTP requests.

The objective was to understand normal network communication, identify relevant packet information and assess whether the observed activity provided evidence of suspicious behaviour.

The investigation identified a DNS AAAA query for `example.com`, an associated DNS response, TCP connection initiation to destination port 80, a completed TCP three-way handshake and visible HTTP requests.

No specific indicators of malicious activity were established from the observations recorded.

## 2. Investigation Objectives

- Capture and inspect network traffic using Wireshark.
- Identify DNS queries and responses.
- Examine TCP connection establishment.
- Identify HTTP requests.
- Evaluate whether the available evidence indicates suspicious activity.
- Document findings using a structured SOC investigation methodology.

## 3. Methodology

### Phase 1 — Packet Capture

Wireshark was used to capture network traffic from the workstation's active network interface.

Normal browsing activity was generated by visiting `https://example.com`.

### Phase 2 — DNS Analysis

The following display filters were used:

`dns`

`dns.qry.name == "example.com"`

A DNS query for `example.com` was identified with record type AAAA, indicating an IPv6 address lookup.

An associated DNS response was subsequently located.

### Phase 3 — TCP Analysis

The following filter was used to identify initial TCP SYN packets:

`tcp.flags.syn == 1 && tcp.flags.ack == 0`

A TCP SYN packet with destination port 80 was observed.

Further inspection confirmed a completed TCP three-way handshake consisting of SYN, SYN-ACK and ACK packets.

### Phase 4 — HTTP Analysis

The following display filter was applied:

`http.request`

HTTP requests were identified within the captured traffic.

The specific HTTP methods, requested resources, destination addresses and response codes were not recorded during this exercise.

## 5. Security Analysis

The observed DNS query was directed at `example.com`, a domain reserved for documentation and testing.

The completed TCP handshake demonstrated successful connection establishment for the examined TCP conversation.

The destination port 80 is conventionally associated with HTTP. HTTP traffic may be transmitted without encryption, making it relevant when evaluating potential exposure of sensitive information.

However, the presence of port 80 traffic does not independently indicate malicious activity.

The observed DNS, TCP and HTTP events were consistent with normal network communication. No evidence was documented to support a conclusion of command-and-control activity, data exfiltration or another network-based attack.

## 6. Limitations

This investigation was based on a short packet capture generated during normal browsing activity.

The following information was not fully documented:

- Source and destination IP addresses.
- Exact packet timestamps.
- DNS response contents.
- HTTP methods, headers and response status codes.
- Relationships between the observed DNS, TCP and HTTP events.
- Historical network behaviour or threat intelligence.

Consequently, the investigation cannot establish that all captured traffic was benign. It can only conclude that the recorded observations did not demonstrate malicious activity.

## 7. Conclusion

The investigation successfully demonstrated practical use of Wireshark to identify and analyse DNS queries, TCP connection establishment and HTTP requests.

No confirmed malicious activity was identified from the documented evidence.

The exercise reinforced the importance of distinguishing observed network behaviour from assumptions about potential security threats.

**Final Assessment:** No confirmed security incident. Baseline network traffic analysis completed.
